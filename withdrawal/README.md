## Procedure

Withdrawal role notation: `peer_0` in the diagrams names the initiator role for
the expanded example, not fixed setup peer index 0. Approval sets are
canonicalized in setup peer order by `peer_ids_collection`.

1. Niso receives psbt from User. Niso checks that most_work_bitcoin_block_height has passed milestone_block_0 from boomerang_descriptor, derives tx_id from psbt and stores it. Niso also checks to see if psbt inputs are satisfiable. It sends the psbt alongside the latest block_height to Boomlet.
2. Boomlet receives {psbt, niso_0_event_block_height} from Niso and checks to see if the niso_0_event_block_height has passed milestone_block_0. Boomlet then derives tx_id from psbt, creates st_preview_nonce, uses st_preview_nonce for ST freshness, encrypts it for st_0_identity_pubkey and sends the envelope to Niso.
3. Niso receives tx_id_with_nonce_encrypted_by_boomlet_0_for_st from Boomlet and forwards it to ST.
4. ST receives tx_id_with_nonce_encrypted_by_boomlet_0_for_st from Niso, decrypts it, separates the nonce and sends the tx_id to User.
5. User receives tx_id from ST and checks to see if it matches that of the psbt he generated. User then informs ST of his acknowledgement of tx_id.
6. ST receives {magic: "withdrawal_initiator_peer_approved_that_txid_received_is_the_same_as_the_one_derived_from_withdrawal_psbt"} from User. ST then signs the tx_id_with_nonce it received with st_privkey and encrypts it with boomlet_0_identity_pubkey. It then sends this encrypted message to Niso.
7. Niso receives tx_id_with_nonce_signed_by_st_encrypted_by_st_for_boomlet_0 from ST and forwards it to Boomlet.
8. Boomlet receives tx_id_with_nonce_signed_by_st_encrypted_by_st_for_boomlet_0 from Niso, decrypts it, verifies st_0_identity_pubkey's signature and checks if the content is the same as the one sent i.e. User has acknowledged the tx_id and the message is fresh. Boomlet then creates initiator_approval_nonce and computes withdrawal_id. It then generates peer_0_tx_approval containing withdrawal_id, initiator_approval_nonce, and event_block_height, signs it with boomlet_0_identity_privkey and encrypts it for wt. It then encrypts psbt for every other boomlet_i using withdrawal_id-bound envelopes. Boomlet sends withdrawal_id, the resulting psbt_encrypted_collection, and peer_0_tx_approval_signed_by_boomlet_0_encrypted_by_boomlet_0_for_wt to Niso.
9. Niso receives {withdrawal_id, peer_0_tx_approval_signed_by_boomlet_0_encrypted_by_boomlet_0_for_wt, psbt_encrypted_collection: Collection<psbt_encrypted_by_boomlet_0_for_boomlet_i> [1 <= i <= 4]} from Boomlet and forwards them to WT.
10. WT receives {withdrawal_id, peer_0_tx_approval_signed_by_boomlet_0_encrypted_by_boomlet_0_for_wt, psbt_encrypted_collection: Collection<psbt_encrypted_by_boomlet_0_for_boomlet_i> [1 <= i <= 4]} from Niso. WT decrypts peer_0_tx_approval_signed_by_boomlet_0_encrypted_by_boomlet_0_for_wt using canonical context {"withdrawal_tx_approval", withdrawal_id}, verifies boomlet_0_identity_pubkey's signature, checks that the signed peer_0_tx_approval carries the same withdrawal_id, and checks that the event_block_height is fresh. Then it constructs its own wt_tx_approval containing withdrawal_id and most_work_bitcoin_block_height and signs it. It sends to each non-initiator peer wt_tx_approval_signed_by_wt, peer_0_tx_approval_signed_by_boomlet_0 and psbt encrypted by that peer's boomlet_identity_pubkey.
11. Non-initiator Niso receives {wt_tx_approval_signed_by_wt, peer_0_tx_approval_signed_by_boomlet_0, psbt_encrypted_by_boomlet_0_for_boomlet_1} from WT. Non-initiator Niso verifies wt_pubkey's signature on wt_tx_approval_signed_by_wt and verifies boomlet_0_identity_pubkey's signature on peer_0_tx_approval_signed_by_boomlet_0. It checks that boomlet_0_identity_pubkey exists in the set of peer_ids_collection. Non-initiator Niso checks that the withdrawal_id values match, peer_0_tx_approval is fresh according to wt_tx_approval, and wt_tx_approval is fresh according to most_work_bitcoin_block_height. It then checks that most_work_bitcoin_block_height has passed milestone_block_0 from boomerang_descriptor and forwards the received message alongside niso_1_event_block_height to Non-initiator Boomlet.
12. Non-initiator Boomlet receives {wt_tx_approval_signed_by_wt, peer_0_tx_approval_signed_by_boomlet_0, psbt_encrypted_by_boomlet_0_for_boomlet_1, niso_1_event_block_height} from Non-initiator Niso. Non-initiator Boomlet verifies wt_pubkey's signature on wt_tx_approval_signed_by_wt and verifies boomlet_0_identity_pubkey's signature on peer_0_tx_approval_signed_by_boomlet_0. It verifies that boomlet_0_identity_pubkey exists in the set of peer_ids_collection, decrypts psbt_encrypted_by_boomlet_0_for_boomlet_1 using boomlet_1_identity_privkey and boomlet_0_identity, and reconstructs withdrawal_id from setup_instance_id, psbt.derive_tx_id(), boomlet_0_identity_pubkey, and peer_0_tx_approval.approval_nonce. Non-initiator Boomlet checks that the reconstructed withdrawal_id matches peer_0_tx_approval and wt_tx_approval, that both approvals are fresh, and that milestone_block_0 has passed. Non-initiator Boomlet then sends psbt to non-initiator Niso.
13. Non-initiator Niso receives psbt from Non-initiator Boomlet. Non-initiator Niso checks that psbt is satisfiable and that the derived tx_id reconstructs peer_0_tx_approval.withdrawal_id under the active setup. It then outputs psbt along with initiator's peer_i_id to non-initiator User.
14. Non-initiator User receives {psbt, initiator_peer_id} from non-initiator Niso. Non-initiator User then informs non-initiator Niso of its agreement with the tx.
15. Non-initiator Niso receives {magic: "withdrawal_non_initiator_peer_approved_the_withdrawal_psbt"} from non-initiator User. Non-initiator Niso then informs non-initiator Boomlet to proceed.
16. Non-initiator Boomlet receives {magic: "withdrawal_peer_agreement_with_psbt_received"} from non-initiator Niso. Non-initiator Boomlet then derives tx_id from psbt, adds st_preview_nonce to it and encrypts it with st_1_identity_pubkey. It then sends tx_id_with_nonce_encrypted_by_boomlet_1_for_st to non-initiator Niso.
17. Non-initiator Niso receives tx_id_with_nonce_encrypted_by_boomlet_1_for_st from non-initiator Boomlet and forwards it to non-initiator ST.
18. Non-initiator ST receives tx_id_with_nonce_encrypted_by_boomlet_1_for_st from non-initiator Niso. Non-initiator ST decrypts tx_id_with_nonce_encrypted_by_boomlet_1_for_st to get tx_id_with_nonce and outputs the content of it i.e. tx_id to non-initiator User.
19. Non-initiator User receives tx_id from non-initiator ST. Non-initiator User checks to see tx_id matches the one he previously received from non-initiator Niso and agreed to. It then informs non-initiator ST of his agreement.
20. Non-initiator ST receives {magic: "withdrawal_non_initiator_peer_approved_that_txid_received_is_the_same_as_the_one_derived_from_withdrawal_psbt"} from non-initiator User. It signs the tx_id_with_nonce, encrypts it with boomlet_1_identity_pubkey and sends the result to non-initiator Niso.
21. Non-initiator Niso receives tx_id_with_nonce_signed_by_st_encrypted_by_st_for_boomlet_1 from non-initiator ST. Non-initiator Niso forwards tx_id_with_nonce_signed_by_st_encrypted_by_st_for_boomlet_1 along with the updated niso_1_event_block_height to non-initiator Boomlet.
22. Non-initiator Boomlet receives {tx_id_with_nonce_signed_by_st_encrypted_by_st_for_boomlet_1, niso_1_event_block_height} from non-initiator Niso. Non-initiator Boomlet decrypts tx_id_with_nonce_signed_by_st_encrypted_by_st_for_boomlet_1 using boomlet_1_identity_privkey to get tx_id_with_nonce_signed_by_st. It then verifies st_1_identity_pubkey's signature on tx_id_with_nonce_signed_by_st and checks if the tx_id_with_nonce received matches with the one sent. Non-initiator Boomlet generates peer_1_tx_approval containing withdrawal_id, approval_nonce, and niso_1_event_block_height, signs it using boomlet_1_identity_privkey, encrypts it with wt_pubkey and sends withdrawal_id with peer_1_tx_approval_signed_by_boomlet_1_encrypted_by_boomlet_1_for_wt to non-initiator Niso.
23. Non-initiator Niso receives {withdrawal_id, peer_1_tx_approval_signed_by_boomlet_1_encrypted_by_boomlet_1_for_wt} from non-initiator Boomlet and forwards them to WT.
24. WT receives {withdrawal_id, peer_1_tx_approval_signed_by_boomlet_1_encrypted_by_boomlet_1_for_wt} from non-initiator Niso, decrypts it using canonical context {"withdrawal_tx_approval", withdrawal_id}, verifies boomlet_1_identity_pubkey's signature on peer_1_tx_approval_signed_by_boomlet_1, checks that withdrawal_id matches the expected value, and checks that the message is fresh according to the most_work_bitcoin_block_height and event_block_height of wt_tx_approval. It also receives withdrawal_id with peer_i_tx_approval_signed_by_boomlet_i_encrypted_by_boomlet_i_for_wt from non-initiator Peers and repeats the same validation process. WT sorts the valid approvals into ordered_peer_tx_approvals in setup peer order and derives ordered_non_initiator_peer_tx_approvals by omitting the initiator's approval. WT then sends ordered_non_initiator_peer_tx_approvals to each non-initiator peer and in a separate message sends ordered_peer_tx_approvals along with wt_tx_approval to the initiator peer.
25. WT collects one valid peer_i_tx_approval_signed_by_boomlet_i from every setup peer, sorts the valid approvals into ordered_peer_tx_approvals in setup peer order, and derives ordered_non_initiator_peer_tx_approvals by omitting the initiator's approval. Each receiver verifies this WT-supplied ordering before computing approved_withdrawal_id.
26. Niso receives {ordered_peer_tx_approvals, wt_tx_approval_signed_by_wt} from WT. Niso verifies each boomlet_i_identity_pubkey's signature on each peer_i_tx_approval_signed_by_boomlet_i and verifies wt_pubkey's signature on wt_tx_approval_signed_by_wt. It checks withdrawal_id to match what was sent, the event_block_heights to be in the appropriate range, and ordered_peer_tx_approvals to contain exactly one approval per setup peer in peer_ids_collection order. It computes approved_withdrawal_id from withdrawal_id and ordered_peer_tx_approvals for local tracking, then forwards ordered_peer_tx_approvals with the latest block to Boomlet.

    26n. Non-initiator Niso receives {ordered_non_initiator_peer_tx_approvals} from WT. Non-initiator Niso updates niso_1_event_block_height with the latest most_work_bitcoin_block_height. For every setup peer except the initiator, it verifies boomlet_i_identity_pubkey's signature on peer_i_tx_approval_signed_by_boomlet_i, checks withdrawal_id to be the expected value, peer_i_tx_approval to be fresh according to niso_1_event_block_height and wt_tx_approval, and checks that wt_tx_approval is still fresh. It verifies the subset is ordered by peer_ids_collection with the initiator omitted, reconstructs ordered_peer_tx_approvals by inserting the stored initiator approval at the initiator's setup peer position, and computes approved_withdrawal_id from the complete ordered set for local tracking. It forwards ordered_non_initiator_peer_tx_approvals alongside niso_1_event_block_height to non-initiator Boomlet.
27. Boomlet receives {ordered_peer_tx_approvals, wt_tx_approval_signed_by_wt, niso_0_event_block_height} from Niso. Boomlet verifies each boomlet_i_identity_pubkey's signature on each peer_i_tx_approval_signed_by_boomlet_i, verifies wt_pubkey's signature on wt_tx_approval_signed_by_wt and updates niso_0_event_block_height with the new value. It checks withdrawal_id to match what was sent, the event_block_heights to be in the appropriate range, and ordered_peer_tx_approvals to contain exactly one approval per setup peer in peer_ids_collection order. It computes approved_withdrawal_id from withdrawal_id and ordered_peer_tx_approvals. It then generates duress_check_space as one randomly sorted list of integers from 1 to 193, including all elements of 1..193, adds a nonce to it and encrypts it. Then Boomlet sends duress_check_space_with_nonce_encrypted_by_boomlet_0_for_st to Niso.

    27n. Non-initiator Boomlet receives {ordered_non_initiator_peer_tx_approvals, niso_1_event_block_height} from non-initiator Niso. After renewing niso_1_event_block_height, for every peer in peer_ids_collection except the initiator, non-initiator Boomlet verifies boomlet_i_identity_pubkey's signature on peer_i_tx_approval_signed_by_boomlet_i, checks withdrawal_id to be the expected value, peer_i_tx_approval to be fresh according to niso_1_event_block_height and wt_tx_approval, and checks that wt_tx_approval is still fresh. It verifies the subset is ordered by peer_ids_collection with the initiator omitted, reconstructs ordered_peer_tx_approvals by inserting the stored initiator approval at the initiator's setup peer position, and computes approved_withdrawal_id from withdrawal_id and the complete ordered set. It then generates duress_check_space as one randomly sorted list of integers from 1 to 193, including all elements of 1..193, adds a nonce to it and encrypts it. Then non-initiator Boomlet sends duress_check_space_with_nonce_encrypted_by_boomlet_1_for_st to non-initiator Niso.
28. Niso receives duress_check_space_with_nonce_encrypted_by_boomlet_0_for_st from Boomlet and forwards it to ST.

    28n. Non-initiator Niso receives duress_check_space_with_nonce_encrypted_by_boomlet_1_for_st from non-initiator Boomlet and forwards it to non-initiator ST.
29. ST receives duress_check_space_with_nonce_encrypted_by_boomlet_0_for_st from Niso, decrypts it to get duress_check_space_with_nonce, maps each integer in duress_check_space through DURESS_DISPLAY_VOCABULARY, creates 5 independently shuffled display columns from the single received list, and keeps display-to-original-index mappings locally.

    29n. Non-initiator ST receives duress_check_space_with_nonce_encrypted_by_boomlet_1_for_st from non-initiator Niso, decrypts it to get duress_check_space_with_nonce, maps each integer in duress_check_space through DURESS_DISPLAY_VOCABULARY, creates 5 independently shuffled display columns from the single received list, and keeps display-to-original-index mappings locally.
30. User receives 5 independently shuffled columns from ST. If he is not being coerced he will select 1 country in each column to replicate the duress_consent_set and inputs it to ST.

    30n. Non-initiator User receives 5 independently shuffled columns from non-initiator ST. If he is not being coerced he will select 1 country in each column to replicate the duress_consent_set and inputs it to ST.
31. ST receives the displayed selections from User, converts them into indices in Boomlet's original single list, then creates duress_signal_index_with_nonce using the nonce from previously received duress_check_space_with_nonce, encrypts it for Boomlet and sends it to Niso.

    31n. Non-initiator ST receives the displayed selections from non-initiator User, converts them into indices in Boomlet's original single list, then creates duress_signal_index_with_nonce using the nonce from previously received duress_check_space_with_nonce, encrypts it for non-initiator Boomlet and sends it to Niso.
32. Niso receives duress_signal_index_with_nonce_encrypted_by_st_for_boomlet_0 from ST and forwards it to Boomlet.

    32n. Non-initiator Niso receives duress_signal_index_with_nonce_encrypted_by_st_for_boomlet_1 from non-initiator ST and forwards it to non-initiator Boomlet.
33. Boomlet receives duress_signal_index_with_nonce_encrypted_by_st_for_boomlet_0 from Niso. Boomlet rejects no outstanding duress check, wrong phase, duplicate response, wrong nonce, wrong count, duplicate indices, or out-of-range indices. If valid, Boomlet resolves the returned original-list indices against the single list in duress_check_space assigning the resulting integers to duress_signal. Boomlet consumes the answer and updates under_duress := under_duress OR (duress_signal != duress_consent_set). The placeholder plaintext is doxing_key_for_sar while the `under_duress` flag is true and zero_bytes_32 otherwise. duress_placeholder_plaintext will be encrypted to make up an approved_withdrawal_id-bound duress_placeholder. Boomlet then constructs peer_0_tx_commit containing approved_withdrawal_id and niso_0_event_block_height, signs it, pads it with duress_placeholder, re-signs it and encrypts it with wt_pubkey and sends the result to Niso.

    33n. Non-initiator Boomlet receives duress_signal_index_with_nonce_encrypted_by_st_for_boomlet_1 from non-initiator Niso. Non-initiator Boomlet rejects no outstanding duress check, wrong phase, duplicate response, wrong nonce, wrong count, duplicate indices, or out-of-range indices. If valid, it resolves the returned original-list indices against the single list in duress_check_space assigning the resulting integers to duress_signal. Boomlet consumes the answer and sets `under_duress` to true on mismatch before selecting duress_placeholder_plaintext. duress_placeholder_plaintext will be encrypted to make up duress_placeholder. Non-initiator Boomlet then computes an approval-set attestation fingerprint from ordered_peer_tx_approvals and wt_tx_approval_signed_by_wt after verifying them, signs the fingerprint with boomlet_1_identity_privkey, and sends it to non-initiator Niso. The attestation means only that it received and verified the complete approval set and computed the same approved_withdrawal_id.
34. Niso receives peer_0_tx_commit_signed_by_boomlet_0_padded_signed_by_boomlet_0_encrypted_by_boomlet_0_for_wt from Boomlet and forwards it to WT.

    34n. Non-initiator Niso receives approval_set_attestation_fingerprint_signed_by_boomlet_1 from non-initiator Boomlet and forwards it to WT.
35. WT receives peer_0_tx_commit_signed_by_boomlet_0_padded_signed_by_boomlet_0_encrypted_by_boomlet_0_for_wt from Niso. It decrypts the message, verifies boomlet_0_identity_pubkey's signature, extracts duress_placeholder and peer_0_tx_commit_signed_by_boomlet_0, and stages them. It does not forward the placeholder to SAR until it has verified the four non-initiator approval-set attestations.

    35n. WT receives approval_set_attestation_fingerprint_signed_by_boomlet_1 from non-initiator Niso. WT recomputes approval_set_attestation_fingerprint from ordered_peer_tx_approvals and wt_tx_approval_signed_by_wt, verifies boomlet_1_identity_pubkey's signature, and requires the signed content to equal the recomputed fingerprint. At the same time it receives approval_set_attestation_fingerprint_signed_by_boomlet_i [2 <= i <= 4] and verifies exactly one matching attestation from each non-initiator Boomlet. Each attestation means only that its signer received and verified the complete approval set and computed the same approved_withdrawal_id. Together with the matching approved_withdrawal_id in the staged initiator commit, the four attestations confirm that all five Boomlets received the complete approval set. After all four verify, WT may forward the staged initiator placeholder to SAR.
36. SAR receives {duress_placeholder, boomlet_0_identity_pubkey, approved_withdrawal_id} from WT. It decrypts duress_placeholder using the Boomlet-to-SAR CBC/CMAC envelope context and sar_privkey to get duress_placeholder_plaintext. It classifies the plaintext as valid safe if it is all-zero 32-byte padding, valid duress if its derived doxing_data_identifier exists, or malformed otherwise. If it was valid duress and the tuple of approved_withdrawal_id, the received boomlet_0_identity_pubkey, and envelope IV of duress_placeholder was not previously saved, SAR activates duress response, uses duress_placeholder_plaintext as doxing_key_for_sar to decrypt static_doxing_data_encrypted_by_doxing_key_for_sar, derives device_data_key from doxing_key_for_sar for each retained upload, derives dynamic_doxing_data_cbc_cmac_keys from device_data_key, decrypts each retained upload's dynamic_doxing_data_encrypted_by_device_data_key with dynamic_doxing_data_cbc_cmac_keys, and makes every retained upload available to SEARCH AND RESCUE. For valid safe or duress placeholders, SAR signs duress_placeholder with sar_privkey and encrypts it with boomlet_0_identity_pubkey. Malformed placeholders are rejected before any acknowledgment is created.
37. WT receives duress_placeholder_signed_by_sar_encrypted_by_sar_for_boomlet_0 from SAR and continues processing peer_0_tx_commit_signed_by_boomlet_0. It verifies boomlet_0_identity_pubkey's signature on peer_0_tx_commit_signed_by_boomlet_0, checks approved_withdrawal_id to be the one expected and event_block_height to be fresh. WT then signs peer_0_tx_commit_signed_by_boomlet_0 with wt_privkey and sends it to non-initiator peers. WT receives each peer i's peer_i_tx_commit_signed_by_boomlet_i in response and checks its correctness in a similar manner. WT then sends the collection of peer_i_tx_commit_signed_by_boomlet_i to Niso alongside duress_placeholder_signed_by_sar_encrypted_by_sar_for_boomlet_0.
38. Non-initiator Niso receives peer_0_tx_commit_signed_by_boomlet_0_signed_by_wt from WT. Non-initiator Niso updates niso_1_event_block_height with the most_work_bitcoin_block_height, verifies wt_pubkey's signature on peer_0_tx_commit_signed_by_boomlet_0_signed_by_wt, boomlet_0_identity_pubkey's signature on peer_0_tx_commit_signed_by_boomlet_0, approved_withdrawal_id to be the expected value, and event_block_height to be fresh according to most_work_bitcoin_block_height. Non-initiator Niso then forwards peer_0_tx_commit_signed_by_boomlet_0_signed_by_wt alongside niso_1_event_block_height to Non-initiator Boomlet.
39. Non-initiator Boomlet receives {peer_0_tx_commit_signed_by_boomlet_0_signed_by_wt, niso_1_event_block_height} from non-initiator Niso. Non-initiator Boomlet verifies wt_pubkey's signature on peer_0_tx_commit_signed_by_boomlet_0_signed_by_wt, boomlet_0_identity_pubkey's signature on peer_0_tx_commit_signed_by_boomlet_0, approved_withdrawal_id to be the expected value, and event_block_height to be fresh according to niso_1_event_block_height. Non-initiator Boomlet then generates peer_1_tx_commit containing approved_withdrawal_id and event_block_height, signs it with boomlet_1_identity_privkey, pads it with duress_placeholder, signs it again and encrypts it with wt_pubkey. It then sends peer_1_tx_commit_signed_by_boomlet_1_padded_signed_by_boomlet_1_encrypted_by_boomlet_1_for_wt to Niso.
40. Non-initiator Niso receives peer_1_tx_commit_signed_by_boomlet_1_padded_signed_by_boomlet_1_encrypted_by_boomlet_1_for_wt from non-initiator Boomlet and forwards it to WT.
41. WT receives peer_1_tx_commit_signed_by_boomlet_1_padded_signed_by_boomlet_1_encrypted_by_boomlet_1_for_wt from non-initiator Niso, decrypts it with wt_privkey, verifies boomlet_1_identity_pubkey's signature. It then derives duress_placeholder by separating the padding from peer_1_tx_commit_signed_by_boomlet_1_padded and sends it to SAR. It also saves peer_1_tx_commit_signed_by_boomlet_1 for later.
42. SAR receives {duress_placeholder, boomlet_1_identity_pubkey, approved_withdrawal_id} from WT. It decrypts duress_placeholder using the Boomlet-to-SAR CBC/CMAC envelope context and sar_privkey to get duress_placeholder_plaintext. It classifies the plaintext as valid safe if it is all-zero 32-byte padding, valid duress if its derived doxing_data_identifier exists, or malformed otherwise.
